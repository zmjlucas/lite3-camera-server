# Security

The native RealSense/V4L2 server assumes the entire local network is trusted. It listens on all IPv4 interfaces by default and keeps anonymous camera access: reachable clients can view frames, inspect camera status and select the shared source. New control POSTs require a separately configured bearer token, including in simulation. Public development status omits token and lease IDs. Requests with an Origin header must match the current origin; this browser check is not access control. Host headers are unrestricted. Use `--bind 127.0.0.1` when starting the server manually if only SSH tunnel access is wanted. Internet exposure is outside this trust model.

SSH is used for deployment, remote startup and optional tunnels, with its existing authentication and host key verification. A native server started by `view` persists independently of clients until explicitly stopped. ROS mode uses an external `web_video_server`; this repository does not add authentication to that upstream server.

Keep SSH host key checks enabled. Do not commit passwords, private keys, tokens, or logs with credentials. Device diagnostics and camera images can contain private information. Before reporting a problem, redact host addresses, usernames, device serial numbers, ROS identifiers, local paths from logs. Keep real hardware session reports outside the repository. Deployment uploads only explicitly allowlisted runtime files and rejects symlinked source paths. Windows deployment also rejects reparse points (including directory junctions) and holds source path handles without write/delete sharing until capture finishes.

Control defaults to simulation. Read-only hardware mode (`readonly`) exposes authenticated arm feedback without any dog UDP output, even on shutdown; all motion and ownership operations are disabled. Hardware output requires an explicit startup mode and private token file. The token is held in browser memory, never URL parameters or browser storage. HTTP does not encrypt it; use the SSH tunnel/loopback on untrusted networks. All token holders are trusted operators; possession grants control/reset/stop privileges. Camera origin checks are not authentication.

One expiring lease owns commands; monotonic sequence numbers and command TTLs reject stale input. A dedicated worker handles dog output independently of camera and arm operations. Reset requires the observed safety revision, preventing delayed resets from clearing newer latches. A supplied stop lease must still own control; an empty observer stop remains available to any token holder. Software emergency stop latches further commands, revokes ownership and attempts dog zero/stationary packets. It cannot guarantee physical stopping. R5 real motion remains blocked after failed hold validation; serial reads may still cause controller reset when a port is opened. The fixed arm helper accepts only feedback queries and never arbitrary code or motion JSON. No unattended deployment or actual motion is performed by offline tests. See [capability and safety boundaries](docs/DEV_SERVER.md#hardware-capabilities).

Both author and committer metadata are public when commits are published. Deleting a file does not remove previously published information from Git history; history cleanup and GitHub-retained references must be handled separately.

Security fixes target `main` first. To report command injection, unintended file access, or another security issue, use the repository's GitHub **Security > Report a vulnerability** form. Include the affected version, steps to reproduce the issue, and its effects. Do not publish credentials or sensitive details of an unfixed vulnerability in a public issue.
