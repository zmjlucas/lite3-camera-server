# Security

The dev server assumes a secure, trusted network with no public internet access. Do not add authentication to the dev server. It listens on all IPv4 interfaces by default. Reachable clients can view frames, select the shared camera source, read status and call control endpoints without credentials. Development status omits the lease ID. Requests with an Origin header must match the current origin. Host headers are unrestricted. Use `--bind 127.0.0.1` when starting the server manually if only SSH tunnel access is wanted.

SSH is used for deployment, remote startup and optional tunnels, with its existing authentication and host key verification. A native server started by `view` persists independently of clients until explicitly stopped. ROS mode uses an external `web_video_server`; this repository does not add authentication to that upstream server.

Keep SSH host key checks enabled. The documented robot defaults (`ysc`, password `'`, perception host `192.168.1.103`, and motion target `192.168.1.120:43893`) can be included in code and examples. Keep private credentials, private keys, and logs that contain them out of the repository. Device diagnostics and camera images can contain private information. Before reporting a problem, remove private host addresses, usernames, device serial numbers, ROS identifiers, and local paths from logs. The documented robot defaults do not need to be removed. Keep real hardware session reports outside the repository. Deployment uploads only explicitly allowlisted runtime files and rejects symlinked source paths. Windows deployment also rejects reparse points (including directory junctions) and holds source path handles without write/delete sharing until capture finishes.

Control defaults to simulation. Read-only hardware mode (`readonly`) provides arm feedback without any dog UDP output, even on shutdown; all motion and ownership operations are disabled. Hardware output requires an explicit startup mode. All clients on the LAN are trusted operators. Any client can acquire available control, reset an observed latch or request a stop, subject to the selected mode.

One expiring lease owns commands; monotonic sequence numbers and command TTLs reject stale input. A dedicated worker handles dog output independently of camera and arm operations. Reset requires the observed safety revision, preventing delayed resets from clearing newer latches. A supplied stop lease must still own control; an empty observer stop remains available to any LAN client. Software emergency stop latches further commands, revokes ownership and attempts dog zero/stationary packets. It cannot guarantee physical stopping. R5 hardware motion is disabled; serial reads may still cause controller reset when a port is opened. The fixed arm helper accepts only feedback queries and never arbitrary code or motion JSON. See [capability and safety boundaries](docs/DEV_SERVER.md#hardware-capabilities).

Both author and committer metadata are public when commits are published. Deleting a file does not remove previously published information from Git history; history cleanup and GitHub-retained references must be handled separately.

Security fixes target `main` first. To report command injection, unintended file access, or another security issue, use the repository's GitHub **Security > Report a vulnerability** form. Include the affected version, steps to reproduce the issue, and its effects. Do not publish credentials or sensitive details of an unfixed vulnerability in a public issue.
